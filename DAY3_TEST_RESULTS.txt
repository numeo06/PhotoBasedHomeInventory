1. HOW THE TESTS WERE RUN
-------------------------
- The real app (real routes, real OWL-ViT detector) was started fresh, so
  the first scan includes loading the model.
- Browser cases: headless Microsoft Edge loaded the real upload page and
  did what a user would do: picked the file, clicked Scan Items, edited
  rows and added an item by hand. The page's resulting state (message
  title and text, rows, buttons) was then read back and screenshotted.
- Server cases: the same uploads were sent straight to POST /scan with
  curl, to prove the server rejects bad files even if the browser's own
  checks are bypassed.
- Missing model: the real model folder was renamed while the server was
  stopped, the case was run, and the folder was renamed back afterwards
  (verified restored).
- Scan error: a separate test server forced the inference step to raise
  an exception. No project file was changed for this.
- The test database was a temporary copy; inventory.db was not touched.
